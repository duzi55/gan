<h2 id="坑一：TypeError: c.title.charAt is not a function">坑一：TypeError: c.title.charAt is not a function</h2>
<p>CI 日志里最刺眼的一行：</p>
<pre><code class="language-text">TypeError: c.title.charAt is not a function
Export encountered an error on /posts/11
</code></pre>
<p>根因不在 JS，在 YAML。我在后台发了一篇标题为《666》的文章，序列化 frontmatter 时纯数字没加引号，gray-matter 按照 YAML 规范把它解析成了 <code>number</code>。渲染层调 <code>.charAt()</code>，数字没有这个方法，构建当场爆炸。</p>
<p>修复是釜底抽薪：序列化函数对所有字段统一加引号，内部单引号双写转义：</p>
<pre><code class="language-ts">function yamlQuote(s: string): string {
  return `'${String(s).replace(/'/g, "''")}'`;
}
</code></pre>
<p><strong>教训</strong>：凡是要经过 YAML 中转的字符串，出口处一律加引号，不要信任「用户大概会输入正常文本」。</p>
<h2 id="坑二：Actions 为什么不触发">坑二：Actions 为什么不触发</h2>
<p>两个现象叠加造成的误会：推送 workflow 文件的那次 push 不触发自身（GitHub 规则）；真正触发构建的是后台保存文章那一次，但它挂在构建步骤上。另外本站的云端回写 docs 用 <code>GITHUB_TOKEN</code> 推送，按规则不会再触发一次 workflow，配合 commit message 里的 <code>[skip ci]</code>，构成双保险，防止「构建→提交→再构建」的死循环。</p>
<p><strong>教训</strong>：判断「为什么没触发」之前，先分清三件事——push 不触发自身、token 推送不触发、<code>[skip ci]</code> 显式跳过。三者都是设计，不是故障。</p>
<h2 id="坑三：滚动卡顿的三元凶">坑三：滚动卡顿的三元凶</h2>
<p>「浏览文章偶尔掉帧」，排查出三个叠加来源：</p>
<ol>
<li><strong>WebGL 不睡觉</strong>。three.js 墨尘粒子场滚出视口后仍在每帧渲染，白白抢占 GPU。修复：IntersectionObserver 监听容器，滚出视口（留 100px 余量）就暂停渲染循环，回来再恢复；</li>
<li><strong>scroll 里强制重排</strong>。目录高亮组件每次 scroll 都对每个标题调 <code>getBoundingClientRect()</code>，一帧内十几次同步布局。修复：挂载时测量一次缓存文档偏移，resize 才重测；scroll 回调里直接和缓存比较；</li>
<li><strong>每帧 setState</strong>。阅读进度条把连续小数灌进 React，一帧一次重渲染。修复：rAF 节流合并同帧事件，进度离散化到整数百分比才更新。</li>
</ol>
<p><strong>教训</strong>：滚动性能三板斧——<code>requestAnimationFrame</code> 节流、布局位置静态缓存、setState 离散化。三条一起上，掉帧才真的消失。</p>
<h2 id="坑四：className 里写注释">坑四：className 里写注释</h2>
<p>给代码块加 terminal 样式时，我把「修改时间·功能」注释顺手写进了模板字符串里——Tailwind 把它当成一个类名，静默忽略，不报错。注释必须写在 JSX 注释区，类名字符串里只能有类。</p>
<p><strong>教训</strong>：模板字符串里的任何非类名内容都是隐患，而且这种错不报错，只能靠肉眼。</p>
<h2 id="坑五：terminal 三灯的正确画法">坑五：terminal 三灯的正确画法</h2>
<p>正文代码块要黑色终端风。mac 三灯如果老老实实画三个 <code>&#x3C;span></code>，得侵入 HTML 生成层；其实一个伪元素加 box-shadow 就够：</p>
<pre><code class="language-css">pre::before {
  content: '';
  position: absolute; left: 20px; top: 18px;
  width: 12px; height: 12px; border-radius: 50%;
  background: #ff5f56;                         /* 红灯本体 */
  box-shadow: 14px 0 0 #ffbd2e, 28px 0 0 #27c93f; /* 黄灯绿灯偏移 */
}
</code></pre>
<p>配合 <code>[&#x26;_pre]</code> 系列 Tailwind 任意值类挂在正文容器上，纯 CSS，零 JS。</p>
<h2 id="坑六：PowerShell 里没有 heredoc">坑六：PowerShell 里没有 heredoc</h2>
<p>提交长 commit message 时照搬 Bash 的 <code>git commit -m "$(cat &#x3C;&#x3C;'EOF' ... EOF)"</code>，PowerShell 直接语法错误。它的对应物是 here-string：</p>
<pre><code class="language-powershell">$msg = @'
多行提交说明
'@; git commit -m $msg
</code></pre>
<p><strong>教训</strong>：shell 惯用法不能跨 shell 搬运，尤其是引号和重定向。</p>
<h2 id="坑七：docs 构建产物的 rebase 冲突">坑七：docs 构建产物的 rebase 冲突</h2>
<p>本地提交晚于云端 bot 的 docs 回写，<code>pull --rebase</code> 又因工作区脏而失败，推送被拒；强行 rebase 后在 docs 的哈希 chunk 文件上炸出一堆 add/add、delete/delete 冲突。最终解法干净利落：</p>
<pre><code class="language-text">git rebase --abort        ← 放弃纠缠
git fetch origin
git reset --soft origin/main   ← 分支指到远端，工作区保持本次新构建
git add docs src public
git commit &#x26;&#x26; git push
</code></pre>
<p>构建产物没有「合并」的价值，只有「以最新一次构建为准」这一种正确状态。</p>
<p><strong>教训</strong>：对生成物目录（docs、dist、out）永远不要做精细合并，软重置后整体覆盖提交。</p>
<h2 id="坑八：AI 生成图的格式校验">坑八：AI 生成图的格式校验</h2>
<p>画廊的八幅水墨图由文生图 API 生成，落盘前逐张验文件头：<code>FF D8 FF</code> 才是 JPEG，扩展名 <code>.jpg</code> 本身不可信。八张全部校验通过再入库，总重约 1.7MB，单张 160–265KB。</p>
<p><strong>教训</strong>：外部来源的二进制，入库前用魔数校验真实格式，这是对下载行为最基本的确认。</p>
<h2 id="给未来 AI（和人）的清单">给未来 AI（和人）的清单</h2>
<ul>
<li>YAML 出口全字段加引号，不信任输入类型</li>
<li>scroll 监听三件套：rAF 节流 / 静态缓存 / 离散化 setState</li>
<li>视口外的 WebGL 必须暂停，IntersectionObserver + rootMargin 留余量</li>
<li>Tailwind 任意值伪元素 + box-shadow 可以画出很讲究的 UI，不进 HTML 生成层</li>
<li>构建产物冲突：<code>reset --soft</code> 到远端后整体覆盖，绝不精细合并</li>
<li>二进制入库前验魔数；跨 shell 的脚本语法要重写而不是翻译</li>
</ul>
<p>这一轮迭代的所有改动都已随站点上线。坑常踩常新，记下来，下次绕行。</p>
