<p>这个博客部署在 GitHub Pages 上。没有服务器，没有数据库，没有进程在深夜里为你守候——只有一堆构建好的 HTML，安静地躺在仓库的 docs 目录里，等谁来读，就把谁的一份拷贝递过去。</p>
<p>于是问题来了：这样的网站，还能有「后台」吗？还能在手机上、在别人的电脑上、在任何一个浏览器里，写一篇文章、点一下保存，然后看着它出现在首页吗？</p>
<h2 id="「后台」到底是什么">「后台」到底是什么</h2>
<p>先把这个词拆开。传统后台做两件事：存内容，渲染内容。而我们其实要的只是：<strong>在任意设备编辑内容，然后让网站更新</strong>。</p>
<p>静态站的答案早就藏在自己的构建流程里：</p>
<ul>
<li>内容的"数据库"——Git 仓库里的 markdown 文件</li>
<li>渲染的时机——不是每次请求时，而是每次构建时</li>
</ul>
<p>所以「在线后台」在静态站上的翻译是：<strong>一个能提交内容的界面 + 一条自动构建的流水线</strong>。前者解决"在哪写"，后者解决"谁来构建"。</p>
<h2 id="一层层的推演">一层层的推演</h2>
<p>这个结论不是一步得出的，值得把推演的路径记下来——每一轮"不行"的背后，都藏着一个值得记录的约束。</p>
<h3 id="第一轮：GitHub 网页编辑">第一轮：GitHub 网页编辑</h3>
<p>仓库页面按一个句号键，就进入 github.dev——GitHub 官方的网页版 VS Code。改 markdown、提交、推送，全程浏览器完成，账号就是钥匙。</p>
<p>它解决了"在哪写"，但没解决"谁来构建"：改完源文件，线上纹丝不动，还是得回到本机跑一次构建。</p>
<h3 id="第二轮：会自己干活的机器人">第二轮：会自己干活的机器人</h3>
<p>GitHub Actions 是官方的免费自动化服务：仓库里放一个剧本文件，声明"当 main 分支收到 push 且 content 目录有变更时，借我一台临时 Linux 服务器，装依赖、跑构建、把生成结果提交回来"。</p>
<p>公有仓库完全免费。它恰好补上了缺的那块：编辑端 push 之后，云端自动构建，Pages 照旧从 docs 目录读取——部署方式一字不改。</p>
<h3 id="第三轮：页面里能藏一把钥匙吗">第三轮：页面里能藏一把钥匙吗</h3>
<p>更进一步的贪心是：在自己博客的某个页面里放个编辑器，点保存就直接发布。这需要页面持有"能写仓库的凭证"。</p>
<p>这里是静态站的绝对红线：<strong>页面里的所有代码，访客都看得到</strong>。把令牌写进前端，等于把仓库钥匙挂在门口。</p>
<h3 id="第四轮：令牌之辨">第四轮：令牌之辨</h3>
<p>那 authenticator 那种动态码行不行？不行，而且要分清两种"令牌"：</p>
<ul>
<li>动态码（TOTP）是登录时的第二道锁，证明"你是你"，它本身不是调接口的钥匙，GitHub 早已封死了密码加验证码调用 API 的路</li>
<li>PAT（个人访问令牌）才是钥匙——生成一次，粘贴一次，长期存放在浏览器里</li>
</ul>
<p>PAT 方案确实可行：令牌不进代码、只进自己的浏览器。但它有一个软肋：换设备要重新粘贴。</p>
<h3 id="第五轮：换设备的终极之问">第五轮：换设备的终极之问</h3>
<p>而 OAuth 授权恰恰为此而生：任何新设备打开后台，点一下「GitHub 登录」，弹窗里点一下授权，钥匙现场发放到这台设备的浏览器。不生成、不复制、不粘贴。</p>
<p>唯一的代价是：GitHub 规定授权的最后一步必须由服务端出示应用密钥。于是需要一段部署在 Cloudflare Worker 上的十几行代码，充当那次几秒钟的"传话人"。</p>
<h2 id="路线的全景">路线的全景</h2>
<p>| 路线 | 电脑上写 | 手机上写 | 换设备负担 | 额外配置 |
|---|---|---|---|---|
| 本机构建推送 | 可用 | 不可用 | — | 无 |
| github.dev + Actions | 可用 | 可用（朴素） | 无 | 一个剧本文件 |
| PAT + 自建后台 | 可用 | 可用 | 重新粘贴一次 | 剧本 + 后台页 |
| OAuth + 自建后台 | 可用 | 可用（顺手） | 点一下授权 | 剧本 + 后台页 + Worker |</p>
<p>每往右一列，体验就顺滑一分，前置配置也重一分。没有最好的方案，只有与自己使用场景匹配的那一行。</p>
<h2 id="约束即设计">约束即设计</h2>
<p>回看整个推演：静态站给不了运行时后端，于是 Git 成了数据库；前端藏不住密钥，于是有了"授权后现场发放"的 OAuth；GitHub 不支持免密钥的授权交换，于是有了边缘函数上的小小网关。</p>
<p>好的方案从来不是绕开约束，而是顺着约束找路。这一轮探讨最终收敛的架构——OAuth 授权、Worker 网关、Actions 构建——三者各占一个约束的出口，拼在一起，静态站便有了自己的后台。</p>
