            [&_code]:rounded [&_code]:bg-foreground/5 [&_code]:px-1.5 [&_code]:py-0.5 [&_code]:font-mono [&_code]:text-[0.85em]8:Td84,<p>写博客总归是想配几张图的。于是问题来了：图放哪儿？</p>
<p>很多人第一反应是「找个免费图床」，或者干脆「单独建一个仓库存图，博客里远程引用」。我起初也这么想，推演了一圈之后发现——对这套 GitHub Pages 博客来说，<strong>图片和文章坐在同一条船上，才是最快的路</strong>。</p>
<h2 id="为什么另开一个仓库反而更慢">为什么另开一个仓库反而更慢</h2>
<p>这个站的所有内容都通过 <code>github.io</code> 分发，背后是 Fastly 的全球 CDN。如果图片放到别的仓库去，会遭遇两件事：</p>
<ol>
<li><strong>raw 直链行不通</strong>。<code>raw.githubusercontent.com</code> 在国内的连通状况比 <code>github.io</code> 还要糟糕，部分地区直接解析失败；而且它返回的是 <code>text/plain</code> 头，某些环境下浏览器不是显示图片而是触发下载。</li>
<li><strong>CDN 中转看运气</strong>。jsDelivr 这类免费前端确实是经典方案，但这几年大陆节点的连通率时好时坏，哪天整段抽风，图文就分家了。</li>
</ol>
<p>而图片放进博客自己的仓库，跟随站点一起发布、一起被 CDN 缓存：同域名意味着<strong>不多付一次 DNS 解析和 TLS 握手</strong>，页面里那张图和标题文字来自同一个地方。</p>
<h2 id="本站的配图规范">本站的配图规范</h2>
<p>所有配图统一存放在 <code>public/images/posts/</code> 目录：</p>
<pre><code class="language-text">public/
└── images/
    └── posts/          ← 文章配图统一在这里
        └── ink-mountain-demo.jpg
</code></pre>
<p>在 Markdown 里引用时带上站点前缀 <code>/gan</code> 即可：</p>
<pre><code class="language-markdown">![远山如黛](/gan/images/posts/ink-mountain-demo.jpg)
</code></pre>
<p>下面这张「远山如黛」就是按此规范入库的真实图片，它的加载速度就是你的读者将来看到的速度：</p>
<p><img src="/gan/images/posts/ink-mountain-demo.jpg" alt="远山如黛：水墨层峦，雾气留白"></p>
<p>顺带的好处：</p>
<ul>
<li><strong>永不断链</strong>——图床跑路是老一代博主最大的痛，图在自己仓库里就没有这回事；</li>
<li><strong>版本可回溯</strong>——改图也走 git commit，历史随时翻；</li>
<li><strong>本地开发可见</strong>——写文章时图片在本地预览就直接显示，不用联网到第三方。</li>
</ul>
<h2 id="瘦身三板斧">瘦身三板斧</h2>
<p>图放对了地方，还要让它足够轻。三个动作，效果立竿见影：</p>
<p>| 手段 | 说明 | 收益 |
| --- | --- | --- |
| 转 WebP | 有损压缩下体积通常再减三至五成 | 显著 |
| 压到显示尺寸 | 页面内容宽约 800px，就别塞四千像素的原图 | 显著 |
| 懒加载 | 首屏之外的图滚动到才加载 | 体感 |</p>
<p>第三条对应的写法是在图片标签上加 <code>loading="lazy"</code> 属性（用 HTML 写法替代纯 Markdown 语法）：</p>
<pre><code class="language-html">&#x3C;img src="/gan/images/posts/ink-mountain-demo.jpg"
     alt="远山如黛" loading="lazy" />
</code></pre>
<h2 id="结语">结语</h2>
<p>配图的答案其实很朴素：<strong>和网站待在一起，然后把自己变得很轻</strong>。不需要注册图床账号，不需要研究外链防盗链，一个目录一把 commit 全解决。</p>
